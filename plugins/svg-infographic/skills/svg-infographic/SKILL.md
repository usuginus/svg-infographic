# SVG インフォグラフィック

テキストや業務要件を整理し、PowerPoint やブラウザにそのまま貼れる単一の SVG を作る。
SVG はレンダラごとに描画が違うため、**PNG に変換して目で確認するまでを 1 セットとする**。

## 手順

1. **伝えることを決める**: スライドを見た人に持ち帰ってほしい結論を 1 文で書く。それを見出しにする。
2. **要素を抜き出す**: 結論を支える事実・ステップ・比較軸を選ぶ。1 つの段（行）に並べるのは 3〜5 個まで。それ以上になるなら、まとめるか図を分けるかをユーザーに確認する。
3. **配置を決める**: 内容に合う並べ方を選ぶ。決まった型に当てはめない。下の「図の型とサイズ」は目安。
4. **SVG を書く**: 部品集 `scripts/svgparts.py` を使い、作業用の一時ディレクトリに生成スクリプトを書く（下の「部品集」）。部品集で描けないものだけ、同じ色・太さの規則で直接書く。
5. **PNG にして確認する**: `Slide.render()`（または `python3 scripts/svgparts.py render in.svg out.png`）で、Chrome 系のブラウザのヘッドレスモードを使い、2 倍解像度の PNG にする。PNG を画像として読み込んで次を確認し、問題があれば直して変換し直す。
   - `save()` が出す「はみ出しの疑い」の警告が無い。警告は文字幅の見積もりなので、出たら PNG で実際に確かめる
   - 文字がカードや枠の端に付いていない、重なっていない
   - 矢印・線・影が出ている。端が切れていない
   - ブラウザは Google Chrome・Chromium・Microsoft Edge の順に探す。見つからないときは、環境変数 `SVGPARTS_CHROME` にブラウザの実行ファイルのパスを入れてもらう
   - macOS の `sips` と `qlmanage` は変換に使わない。`sips` は太さを 2 段階（500 以下は細字、600 以上は極太）でしか描けず、`text-anchor="middle"` の文字が右にずれる。`qlmanage` は正方形に切り抜く。ブラウザがどうしても使えないときだけ `sips` を使い、太さと中央寄せが正しく出ないことをユーザーに伝える
6. **渡す**: ユーザーが PNG を見られるようにし（画像を表示できる環境なら表示する）、SVG と PNG の絶対パスを伝える。何を載せ、何を省いたかを書く。ユーザーがコードを求めたときは ```xml ブロックで SVG 全文も出す。

## 部品集（scripts/svgparts.py）

色・文字サイズ・太さ・余白を部品の中で固定してある。図ごとに見た目が変わらないよう、カード・矢印・バッジなどはこの部品で描く。見た目を変えたいときは部品集のほうを直す。

`<このスキルのディレクトリ>` は、スキルを読み込んだときに示されるディレクトリ（Base directory for this skill）に置き換える。

```python
import sys
sys.path.insert(0, "<このスキルのディレクトリ>/scripts")
from svgparts import Slide, C

s = Slide("図のタイトル", "図の内容を一文で書く（aria-label になる）")
s.header("結論を書いた見出し", "右上の補足（チケット番号など）")
s.stats(60, [("止まった時間", "約 15 分", C.ORANGE), ("影響した予約", "120 件", C.TEXT)])
s.section(152, "段の見出し")
s.flow(166, [("見出し", ["説明 1 行目", "説明 2 行目"], None), ("結果", ["…"], C.ORANGE)])
s.save("/path/out.svg")
s.render("/path/out.png")
```

| 部品 | 用途 |
|---|---|
| `header(title, meta)` | スライドの見出しと右上の補足 |
| `section(y, title)` | 段の見出し |
| `stat` / `stats` | ラベルと数値の組（横一列に並べるなら `stats`） |
| `flow(y, items)` | 矢印でつないだ横並びのボックス。強調色を渡すと枠と見出しがその色になる |
| `card` / `pill` / `status` / `bullets` | カード、番号・分類のバッジ、状態の表示、箇条書き。組み合わせて独自のカードを作る |
| `table(x, y, w, headers, col_x, rows, highlight)` | 表。highlight の行は背景を淡い青にする |
| `steps(x, y, items)` | 縦に並ぶ番号付きの手順 |
| `arrow` / `arrow_down` / `line` / `dot` / `numbered` | 線と記号 |
| `columns(n, gap)` | 左右の余白の内側を n 等分した幅と x 座標 |
| `text(..., max_width=)` | 文字。max_width を渡すと、はみ出しの疑いを警告する |
| `icon(name, x, y, size, color)` | 線画のアイコン（下の一覧） |
| `titled(x, y, icon, title)` | アイコン付きのカードの見出し |
| `stat(..., icon=)` | 数値カードの右側にアイコンを置く |
| `ratio(x, y, w, label, value, color, part_label, fraction)` | 全体の値と、そのうちの割合を 1 本の帯で示すカード |
| `node(x, y, w, h, icon, title, sub, accent)` | 図解の要素（人・システム・データなど）。アイコン・名前・説明を中央そろえで書く |
| `chain(y, items)` | node を横一列に並べて矢印でつなぐ。誰や何を経由したかを示す |
| `connector(x1, y1, x2, y2, label=)` | 任意の向きの矢印。node を縦や斜めにつなぐときに使う |
| `zone(x, y, w, h, label)` | 持ち主や環境の区域を示す破線の枠。中に node を置く（自社のシステムと外部のサービスの境目など） |
| `span(x1, x2, y, label, color)` | 横に並んだ要素の範囲を示す線とラベル（「メールを送る前」「送った後」など） |
| `timeline(y, items)` | 時刻順の出来事を等間隔に並べる。間隔が時間の長さに比例しないことを段の見出しに書く |
| `decision` / `box` / `terminal` | 分岐図の判断（淡い青の角丸）・処理（四角）・終わり（ACK・NACK・完了など。色で結果の意味を示す） |
| `elbow(pts)` / `edge_label(x, y, label)` | 縦横に折れる矢印と、矢印に添える「はい」「いいえ」などのラベル（背景を塗って線と重ねない） |
| `sketch(x, y, w, h, xlabels, ylabel)` | 模式図の枠。戻り値の `line` / `area` / `label` で 0〜1 の座標に描く。「模式図（実際の値ではない）」を自動で書く |
| `scale(x, w, v0, v1)` / `band(x1, x2, y, h, color, label)` | 値を座標に写す関数と、時間帯や範囲を示す帯。時間に比例した軸を作る |
| `range_bar(x, y, w, label, lo, hi, vmax, value)` | 最小〜最大を示す横棒 |

アイコンは `user` `users` `building` `server` `database` `laptop` `ai` `container` `wallet` `coin` `point` `warning` `check` `clock` `lock` `key` `document` `bell` `flag` `shield` `search` `queue` `workflow` の 23 種類。形は `python3 scripts/svgparts.py icons out.png` で一覧にして確かめる。足りないアイコンは `ICONS` に足し、一覧で形を確かめてから使う（線だけで描き、24×24 の格子の 2〜22 の内側に収める）。

## スライドとして読みやすくする基本

- **1 枚で伝えることは 1 つ**。見出しには話題の名前ではなく結論を書く（「原因」ではなく「原因：月曜の朝に図書館の予約が集中し、検索サーバーの CPU が上限に達した」）。
- **読む順番を配置で示す**。左から右、上から下に読むことを前提に、概要 → 詳細、原因 → 結果の順に置く。
- **情報の重要度を大きさ・太さ・色の 3 段階で揃える**。見出し → 段の見出し → カードの見出し → 説明文の順に小さく、薄くする。同じ階層の要素は同じ見た目にする。
- **揃える**。左端・上端・間隔をそろえる。同じ段のカードは同じ幅と高さにする。`columns()` で割り付けると自然にそろう。
- **関係のあるものを近くに、無いものを離す**。カード内の行間（18〜24px）より、カード同士の間隔（12px 以上）と段どうしの間隔（30px 以上）を広くする。
- **色には意味を 1 つずつ持たせる**。オレンジは問題点、グリーンは完了・到達点、青は番号と新規。それ以外の色を足さない。意味の無い色分けをしない。
- **文字を減らす**。1 項目の説明は 2 行まで。文ではなく、事実を短い句で書く。数値には単位を付ける。
- **装飾を足さない**。グラデーションや影の強調は入れない。アイコンと図解は、次の節の規則に合うときだけ使う。
- **元資料の用語をそのまま使う**。同じものを図の中で別の言葉で呼ばない。

## アイコンと図解を使う場面

**1 枚に 1 つ、結論を示す主な図を置く。文字のカードはその補足にする。** 箇条書きにしようとした内容が次のどれかに当たるなら、図にする。

- **図解を使う場面**
  - 人・システム・データのあいだを何かが渡る、または順に経由する → `chain` / `node` / `connector`、持ち主や環境の境目は `zone`
  - 条件で行き先が分かれる手順（「対象外なら ACK」「失敗したら NACK」など） → 分岐図（`decision` / `box` / `terminal` / `elbow` / `edge_label`）。出口が複数ある手順を箇条書きにしない
  - 分類ごとに動きが変わる（エラーの分類など） → 分類から動き、結果へ矢印でつなぐ。くり返しは `elbow` でループの矢印にする
  - 量が時間でどう変わるか、上限との差（バックログ、容量と負荷など）が要点 → 模式図（`sketch`）。実データではないと図の中に書く
  - 時刻や時間帯の重なりが要点 → 時間に比例した軸（`scale` / `band`）。等間隔の `timeline` は、時刻の順番だけを示したいときに使う
  - 範囲（応答時間 120〜300 ms など）の大小が要点 → `range_bar`。数値を正確に比べるグラフは、グラフ用のライブラリやスキルで作る
  - 全体のうちの割合が要点 → `ratio`
  - 範囲の区切り（「メールを送る前」と「送った後」など） → `span`
  - 変更前と変更後の違い → 左右にカードを並べ、変わった部分だけに色を付ける
  - 文字のボックスの列（`flow`）は、分岐の無い手順や原因の連鎖に使う
- **矢印の描き方**
  - 矢印は 28px 以上の長さにする（`elbow` と `connector` は短いと警告を出す）。短いと先端がつぶれて、向きが分からない。ノードを横に並べるときは、間隔を 40px 以上にする
  - 矢印の上下にラベルやアイコンを置くときは、間隔をラベルの幅＋20px 以上にする。番号（①②）は、同じ図の別の番号付けと重ならないときだけ使う
  - 「はい」「いいえ」などのラベルは線の上に重ねない。縦の矢印は線の右横、横の矢印は線の上に置く
  - 分岐図は、要素の間隔を先に決めてから要素を置く。要素の高さを詰めてでも、矢印の長さを確保する
- **時期によって変わる数値は載せない**: 顧客数・注文件数・割合・現在の設定値（rps など）・所要時間は、資料を見る時期によって違う値になる。仕様の値（有効期限・保持期間など）は載せてよい。判断の根拠として実測値を載せるときは、測った時期と「変わる」ことを図の中に書く
- **文字のまま残すもの**: 条件や注意事項の一覧（「インシデントとして扱うもの」など）。図にしても情報が増えない
- **アイコンを付ける場面**
  - 種類を見分けると理解が速くなる要素（人・システム・お金・状態・時刻）だけに付ける。すべてのカードに付けない
  - 1 つの要素に付けるアイコンは 1 つまで
  - 同じ図の中で、同じものには同じアイコンを使う。違うものに同じアイコンを使わない
  - 色は補足テキストの色（`C.SUB`）にする。強調したい要素だけ、その要素の強調色（オレンジかグリーン）にそろえる
  - 大きさは 22〜24px。文字より目立たせない
- **使わないもの**
  - 写真・イラスト・画像生成 AI の画像。見た目がそろわず、中の文字を直せない
  - 外部のアイコン集。使う場合はライセンスを確認し、ファイルのダウンロードについてユーザーの許可を得る

## 言葉づかい

- **比喩を使わない**。文字どおりの言い方を使う。文字数が増えても、直接的な表現を選ぶ。
  - 「火消しをする」ではなく「障害に対応する」。「交通整理をする」ではなく「担当と順番を決める」。「ボトルネックを潰す」ではなく「処理が遅い箇所を速くする」。「二枚看板」ではなく「2 つの主な機能」。
  - 元資料が「爆速化」のように比喩を使っていても、図では「処理時間を 2 分の 1 にする」のように言い換える。
- 擬人化（「仕組みが守った」）や、程度をぼかす言い方（「かなり」「大きく」）を使わない。数値があれば数値で書く。
- 会話文の説明（図を渡すときの報告）も同じ規則で書く。

## 図の型とサイズ

| 型 | 例 | サイズ |
|---|---|---|
| 業務フロー | 水平ステップ・分岐・スイムレーン | 960×240〜320 |
| ロードマップ | 四半期タイムライン・フェーズ別マイルストーン | 960×240〜320 |
| 比較表 | 機能比較・料金プラン・メリット/デメリット | 960×540 |
| 階層・ピラミッド | 組織図・戦略レイヤー・DIKW | 960×540 |
| 解説スライド | インシデントのふりかえり、PR の変更点、施策の全体像 | 960×540 |

- スライド 1 枚に貼る図は 960×540（16:9）を基本にする。800 幅だとスライドの左右が余り、同じ文字サイズでも詰まって見える。
- 余白は外側 24px、カード内側 20px（横並び 5 枚のボックスは 16px）を目安にする。
- `width` / `height` と同じ値の `viewBox` を必ず付ける（部品集は自動で付ける）。

## 文字

- フォント: `'Hiragino Sans', 'Yu Gothic UI', 'Noto Sans JP', system-ui, sans-serif`。`system-ui` だけだと Windows で和文のフォントが安定しない。
- サイズ: 見出し 20px、段の見出し 15px、カードの見出し 14〜15px、数値 16px、説明文 12〜13px。**12px 未満は使わない**（スライドに縮小・投影すると読めない）。
- 太さ: **700 は使わない**。和文の 700 は重く、図全体が黒く見える。
  - 600: 見出し・段の見出し・カードの見出し・バッジだけ
  - 500: 数値、補足のラベル
  - 400: 説明文
  - 強調は太さより色で付ける。太字の要素が増えると、どこが重要か分からなくなる。
- **SVG に自動改行は無い**。改行位置は自分で決め、行ごとに `text()` を呼ぶ。
  - 幅は全角 1 文字 ≒ font-size px、半角英数 ≒ 0.62 × font-size px で見積もる（`text_width()`）。
  - 語の途中で折らない。助詞の後や「・」の後で折る。

## 描画の互換性（レンダラによって結果が変わるもの）

- **`<marker>` は使わない**。sips では矢印の先端が描画されなかった。矢印は線と先端を 1 本の `<path>` で描く（`arrow()`）。
- 色・サイズは要素の属性に直接書く。`<style>` の CSS クラスは、PowerPoint など一部のレンダラで効かないことがある。
- 影（`feDropShadow`）は Chrome と sips では出るが、レンダラによっては無視される。影が出なくてもカードの区切りが分かるよう、枠線も付ける（`card()`）。
- 外部画像（`<image href>`）・外部フォント・`<foreignObject>` は使わない。アイコンは `<rect>` `<circle>` `<path>` `<polygon>` で描く。
- `<title>` と `aria-label` に図の内容を一文で書く（`Slide()` の引数）。
